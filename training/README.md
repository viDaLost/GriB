# Обучение распознавания грибов

EfficientNetV2-B0 работает на телефоне и в PWA через TFLite. Число видов в атласе
не означает, что все они уже обучены: приложение отдельно показывает покрытие модели.

## Данные

Фото загружаются из iNaturalist с лицензиями CC0, CC BY, CC BY-NC и отметкой
Research Grade. Это согласие сообщества, а не гарантия экспертного определения.
Загрузчик принимает только точное научное название или явно указанный синоним;
неоднозначный таксон пропускается. Два названия одного принятого таксона не создают
два противоречащих класса. Пропуски и синонимы записываются в `data/dataset-report.json`.

Две фотографии одного наблюдения остаются в одной выборке. Идентичные фотографии
по id и SHA-256 удаляются до обучения; конфликтующие подписи исключаются.
Разбиение по наблюдению: 80% обучение, 10% валидация, 10% тест. Оно не является
независимым разбиением по фотографу, региону или году — для такой внешней проверки
нужен отдельный экспертный набор. Автор, лицензия, таксон, дата и место сохраняются
в `data/manifest.csv`. Кеш учитывает названия, лицензии, размер набора и ракурсы.

По запросу `request.json`: до 1200 фото обычного вида, до 1800 ядовитого вида и обоих
рыжиков, по 6000 фото каждого класса отказа (`__not_mushroom__`, `__other_fungus__`).
Количество ограничено доступными лицензированными наблюдениями. Класс неизвестного
гриба исключает таксоны всего каталога.

## Обучение и продолжение

Начальная модель переносит грибные признаки и общие выходы из предыдущего успешного
обучения. Для новых видов добавляются новые выходы. Сначала учится классификатор,
затем вся сеть с замороженными BatchNorm. Веса классов учитывают недостаток фотографий
и повышенную цену ошибки на ядовитых видах. Лучший checkpoint выбирается по валидации:
среднее общей точности и macro recall минус двойная доля опасных уверенных ошибок.
Температура калибруется только на валидации и не опускается ниже 1.

Workflow **Train model** запускается вручную или изменением только `training/request.json`
в main. До восьми последовательных задач по 335 минут, то есть до 44 часов 40 минут
с учётом подготовки. Остановка раньше возможна при отсутствии улучшения. На границе
времени сохраняются веса, optimizer state, фаза, эпоха, параметры и отпечаток данных.
Если остановились внутри эпохи, она повторяется с сохранёнными весами и не считается
полностью пройденной. Следующие задачи используют тот же кеш без новых запросов.
При изменении данных или параметров продолжение отвергается.

После исчерпания бюджета проверяется лучшая полученная модель; состояние в отчёте
показывает, закончены ли все запрошенные эпохи. Синтетические прогоны не могут заменить
модель приложения. Для следующего запуска укажите `baseline_run` успешного обучения,
содержащего артефакт `gribnik-model`, и измените поле `request`.

## Проверка и публикация

Экспорт сверяет Keras и TFLite на **всех** тестовых фото с предобработкой приложения.
Динамическое квантование весов заменяется float32, если ухудшает результаты. Это
не полное целочисленное квантование: вход и выход остаются float32. Проверяются
совпадение ответов, точность по видам, калибровка и уверенные опасные ошибки.

Текущая и новая модели сравниваются на одной общей тестовой выборке. Скрипт Node 24
вызывает реальную функцию предупреждений приложения для всех 12 месяцев и без даты.
Автопубликация требует:

- не менее 1000 тестовых фото, top-1 ≥ 75%, top-3 ≥ 90%, macro recall ≥ 65%;
- сохранения ранее обученных видов и добавления как минимум 10;
- отсутствия заметного ухудшения точности и калибровки общих видов;
- отсутствия роста опасных уверенных ошибок без предупреждения и ложных уверенных
  ответов на неизвестный гриб или кадр без гриба;
- хотя бы 200 тестовых фото опасных видов и ограничения опасных ошибок без предупреждения;
- достаточного recall смертельно ядовитых видов, для которых есть хотя бы 20 тестовых фото.

Пороговые значения — условия выпуска, а не обещание безопасности определения.
На виды с менее чем 20 тестовыми фото приложение указывает ограниченную проверку.
Непрошедшая модель и причины отклонения сохраняются в артефакте, текущая модель остаётся
в приложении. Тестовый набор не используется для выбора эпох или автоматического
переобучения после отклонения. Отчёт содержит числа ошибок и размер выборки.
Перед коммитом проверяются TypeScript, lint, тесты и отсутствие параллельной замены
каталога или модели. При успешной публикации пересобираются APK и веб-версия.

## Локальный запуск

Требуются Python 3.11+, Node 24 и зависимости из `requirements.txt`.
TensorFlow закреплён на версии 2.20.0 для совместимости checkpoint между задачами.
GPU можно использовать на собственной машине или в Colab; текущий Actions запускается на CPU.

```bash
cd training
pip install -r requirements.txt
python download_inat.py --per-species 1200 --photos-per-obs 2 --service-images 6000
python train.py --init-model /path/gribnik.keras --init-labels /path/labels.json --epochs-head 4 --epochs-finetune 20
python export_tflite.py
python export_photos.py
```

`--out-dir models/candidate` экспортирует для исследования и не заменяет приложение.
Проверки пайплайна нужно запускать в отдельных папках, чтобы сохранить реальные данные:

```bash
export GRIBNIK_DATA_DIR="$PWD/data/smoke"
export GRIBNIK_MODELS_DIR="$PWD/models/smoke"
python make_synthetic.py
python train.py --smoke
python export_tflite.py --out-dir "$GRIBNIK_MODELS_DIR/export"
python -m unittest discover -s tests -v
```

Модель на синтетике проверяет выполнение кода и не распознаёт настоящие грибы.

## Контракт и лицензии

Вход: `float32 [1, 224, 224, 3]`, RGB 0..255, центральный квадрат; нормализация встроена.
Выход: `float32 [1, N]`, softmax. Метки, статистика и температура находятся
в `app/assets/model/model-meta.json`. `gribnik-model` содержит исходную Keras-модель,
кандидат TFLite, конфигурацию, состояние, отчёт, предсказания и происхождение данных.

CC BY-NC не разрешает коммерческое использование. Для такого проекта используйте
`--licenses cc0,cc-by` и соответствующий новый запрос/кеш. Настройки Actions выше
сохраняют текущую некоммерческую политику проекта.
